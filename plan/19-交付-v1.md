## 1. 最重要的一条：时钟原来是错的

`src/clock.py` 写着 `BPM = 167.65, PHASE = 0.235`，交接文档 §7-6 标注"没有交叉验证"。我做了交叉验证，**它是错的**：

| 来源 | 结果 |
|---|---:|
| `librosa.beat.beat_track`（全曲） | **112.35 BPM**（731 拍） |
| `librosa.feature.tempo` | 112.3 BPM |
| dsh-soundcheck（全曲） | 112 / 56 BPM |
| 鼓轨起音 DFT（212–246 s） | 111.2 / 113.0 BPM（峰在 1.853 / 1.883 Hz） |
| 鼓轨起音归一化自相关 | 113.2 BPM（lag 0.530 s） |
| 原来的组合谱通量扫格 | 167.65 BPM |

**167.65 与 112 是 3:2 关系**——四分音符与附点/三连音细分的关系。在 shuffle 律动上做纯 BPM 梳状扫描，
很容易锁到 3 那一侧，报出 1.5 倍速度。原来就是这样错的。

**为什么不直接除以 1.5**：实测拍间隔本身在漂（60–120 s 段 105.5 BPM，其余 112.3 BPM），
解析式网格会持续累积误差。所以改成**查表**：`data/beat_times.json` 存 731 个实测拍点，
`clock.py` 全部改为查表（`beat_index/beat_t/beat_pos/pulse/snap/grid`）。
仍是纯函数——表跟公式一样确定，任意单帧照样可独立重渲。

> 影响面：`pulse()` 现在真正落在鼓上。原来 1.5 倍速的脉冲，等于全片每三次呼吸有两次是空的。

### 3.2 四轨包络真正接进画面（`drive.py`）

交接文档 §7-3 说"代码已写，未接进 `scene.py`/`preview.py`"。现在按 plan/17 §7 的表接了：

| 轨 | 驱动 | 实现 |
|---|---|---|
| `vocals` | 光柱亮度高度 | `entity * w_beam * (0.18+0.82*vocals_smooth)` —— 间奏 124 秒光柱自然熄灭 |
| `bass` | 山脊振幅 | `amp_scale * (0.74+0.55*bass_smooth)`，用均值不用峰值（峰值保持会抖） |

| `drums` | **阈值事件**，不是滑杆 | `drum_hit()` 只在起音超阈时返回一个 `pulse`（plan/07 §2.1：量化优于连续） |

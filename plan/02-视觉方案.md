## 1. 我的意见（先说结论）

**不要照原片做"双屏 AI 聊天"。** 原片那套（左边 dsh 聊天窗口 / 右边模型内部）是给《world.execute(me);》的歌词内容量身长的——歌在唱"执行我、把我写进世界"，所以"界面 vs 世界"成立。张雨生这首歌唱的是**山、花、离开和记得**，硬套一个 AI 聊天窗口只会让人出戏。

**这首歌自带的视觉母题是"卡拉OK"。** 它出自专辑《卡拉OK·台北·我》，唱片歌词页里那四个口令——`（啊预备唱）`、`（第二步）`、`（升key）`、`（再升）`——是**唱片自己写进歌词的演出指令**，不是乐评附会。也就是说：这首歌本身就在扮演"一次带唱的录音"。

所以我的方案是：**把它拍成一台 1994 年的点唱机，在一次演唱里慢慢看见一座山。**

- **左屏**：点唱机 / 字幕机的操作界面（TUI）。曲目号、跑马歌词、评分、电平、播放列表。
- **右屏**：歌里那座山。兰花草、雨、日落、花田、螺旋。
- **全片是一次"机器记录一次演唱"的过程**：前奏机器还没亮，唱到升 key 时界面过载，最后一句唱完机器关掉，只剩一行 `[ 谢谢收听 ]`。

一句话：**左边是 1994 年的机器，右边是 1994 年的山，中间是这首歌。**

## 2. 三条硬规则

| 规则 | 内容 | 为什么 |
|---|---|---|
| **不画人** | 右屏没有具象角色。"她"是一根**信号光柱**（极光带 + 少量字符），随音量呼吸、随升 key 崩解 | 规避角色版权；也避免廉价感——6 分半靠山和光已经够撑 |
| **字符是介质，不是装饰** | 界面全部是等宽字符网格；右屏的地形是**实心形状 + 字符颗粒**，不是全字符画 | 纯字符画在 720p 下会糊成噪点（我试过，见 v0.1）；"形状 + 颗粒"既有 TUI 味又保得住剪影 |
| **一切可复现** | 每帧 = `f(t)`，无跨帧状态，随机数按镜头播种 | 分块并行不改像素；任何一帧可以单独重渲 |

## 3. 视觉语言

- **画布**：1280×720 / 24 fps。左屏 384 px，右屏 872 px，中间 8 px 缝。
- **色**：左屏琥珀 `#FFB000`；右屏深蓝 `#4D6BFE → #C4D4FF`；升 key 时整体色温 +30%（见静帧 04）。红 `#FF3A28` 只给口令和告警。
- **字**：Consolas（界面/数字，9×16 网格）、微软雅黑（歌词/中文标题）。**Consolas 没有块字符**，所以 `█▒▓` 这类一律不用——这是踩过的坑。
- **后期**：bloom（0.3×）+ 扫描线（每 3 行）+ 暗角。克制，不要糊。
- **动态语法**（写进渲染器，不是逐帧画）：
  - 地形随 `t` 缓慢起伏（噪声的第三个维度用时间）；
  - 信号光柱的极光带频率跟音量走；
  - 雨速跟节拍走（BPM ≈ 167，八分音符 0.18 s）；
  - 每轮 A 段整体提亮 +8%，第四轮加反相闪帧；
  - 升 key 用**放射光束**（additive，不会压暗天空）而不是螺旋——螺旋试过，读起来像靶心。

## 4. 专辑封面（代码绘制）

封面不引用原版图片，**全部用代码画**：一轮低太阳、三层山脊、一株花、左下角标题、右上角编号 `UFO-9405`。同一个函数 `cover(box, t)` 在两处复用：

- **开场卡（0–3 s）**：460×480 大封面居中，右侧是作词/作曲/编曲/制作人四行字幕 + `LOADING DISC` 进度条 —— 对应 LRC 里 0–3 s 那四行制作人字幕；
- **左屏曲目块（全片）**：120×120 小封面，贴在曲目号旁边。

这样"封面"既是道具也是转场：开场时它占满画面，唱起来之后缩进机器里。

## 7. M0 音频结论（影响时间轴）

- LRC 时间戳**整体比实际人声早约 0.4–0.9 s**（53 行交叉相关，位移 +0.90 s 时相关度翻倍；对齐后首音离散仅 ±5 ms）。**做片时必须加全局偏移**，否则歌词永远早半拍。
- 结尾**不是"最后一句直接收"**：最后一句 386.00 s 起唱，之后是 8 秒渐弱，394.5 s 才真正静音。尾段可以放心做 8 秒的淡出。
- 起唱前有 **1.06 s** 静音，开头的制作人字幕可以放在这段里。
- 速度 ≈ **167 BPM**（八分音符 0.18 s），四轮 A 段逐轮升 key。

## 8. 主题层（v2 新增）：从"看山"改成"改写"

外部文档 v2 的第 8 节给了一个更硬的读法：**这不是"顺手改民歌"，是一首关于"谁有资格重写"的歌**。四条文本位移（`我从山中来` → `谁从山中来`、`希望花开好` → `也曾勤灌溉长得一园好`、`一日望三回` → `茶花樱花满山开`、`祝汝满盆花` → `谁记得曾经有那一盆`）全部指向同一件事：**被唱成公共财产之后，最初那一株、那个人、那份心思就没了**。

这直接改掉我原来的方案重心。原方案是"机器记录一次演唱"；现在应该是：

> **机器在放一首旧歌，而这首歌正在屏幕上被当场改写。**

### 8.1 改写层（新增的第三条视觉线）

左屏的歌词 LCD 不再只显示当前句，而是显示**两行**：

```
REWRITE 01
我 从山中来 带着兰花草     ← 胡适《希望》原句，灰色，划掉
谁 从山中来 带着兰花草     ← 新句，蓝白，红框光标停在被改的字上
```

**一个字的替换就是全片的论点**：`我` → `谁`。之后每次改写都记一次数（`REWRITE 02/03/04`），到 B 段变成"索取工具"（给我吉他/铅笔/翅膀/空间），到结尾 `谁记得` 时数字停在 04。

静帧见 `07-rewrite-070s.png`。技术上这是字符网格上的一次 diff 动画：旧句逐字变灰 → 划掉 → 新字逐笔打上去，光标是红色方块，和机器同色系。

### 8.2 机器不是中立的

专辑文案在拆"制作人 = 卡拉OK 带子的制造者"这个角色，而这首歌后半段**张雨生自己变成了带唱的人**（预备唱/第二步/升key/再升 + 六人齐唱）。所以左屏这台机器：

- 前半段是**别人的机器**：标准界面、标准评分、标准跑马字幕；
- A② 之后**被他接管**：口令开始出现、评分失控（96.8）、播放列表被挤到边上；
- 最后 13 秒：机器打出 `GAME SET`，画面**硬切**——对应专辑文案最后一句"他必须对所有参与的人说：Game Set!"，而这首歌正好是第 13 首、专辑末曲。

### 8.3 121 秒间奏：不是一段 solo，是五段

我对间奏做了能量/频谱/起音统计（8 秒窗），它不是平的：

| 时间 | 电平 | 频谱重心 | 起音密度 | 判断 |
|---|---:|---:|---:|---|
| 122–146 | −19 ~ −22 dB | 2300–2600 Hz | 17–30% | 全乐队，最亮 |
| 146–162 | **−35 ~ −46 dB** | **650–850 Hz** | **0%** | 骤静，低音区，几乎无起音 |
| 162–202 | −30 ~ −33 dB | 1200–1800 Hz | 0–5% | 长音独奏，缓慢上行 |
| 202–210 | −25 dB | 2235 Hz | 6.6% | 起势 |
| 210–246 | −21 dB | 2280–2590 Hz | 23–37% | 全乐队回归 |

所以间奏应该拆成 **5 个镜头**而不是 1 个长镜头：`全奏 → 骤静（画面几乎全黑）→ 长音独奏（一条横向光带缓慢移动）→ 起势 → 回归`。静帧 `08-break-solo-176s.png` 是第二段"长音独奏"的样子。

### 8.4 一个被数据否掉的想法

唱片内页写间奏是**江建民（左声道）/ 李庭匡（右声道）两把吉他**。我本来想做"左屏跟左声道、右屏跟右声道"的双声道视觉。实测：**这张母版几乎是单声道**——左右相关度 0.90–0.99，Side 分量比 Mid 低 65–85 dB，间奏里的左右差只有 1–4 dB。所以这个方案**不成立**，改用上面的能量/频谱分段驱动。

（如果以后拿到真正分轨的版本，这个想法可以复活。）
